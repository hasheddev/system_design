Strategies
Pull strategy: tell cdn provider which content to cache and how often to cache
This is configured by setting a TTL property on each type of asset or asset
In this case cache is population only on user request first then resource served from it
In case of expiry cdn request for resource and if valid refreshes expiry if not it replaces it with the new one on user request for the resource

Push: We automatically publish content to cdn and we republish on change to cdn
Some Cdns providers support this directly while others enable it by setting ttl for assets so the cache never expires and we purge the cache
forcing the cdn to fetch the content from our servers whenever a user requests it

Pull startegy has lower maintenance on our part everything is taken care of by provider but first users have more latency when product is not cached
If assets expire at the same time we see a traffic spike and we get a large number of requests from cdn to refresh cache
It needs hight availability as user will get an error if cdn asset expires and system is unavailable for cdn to pull new version

Push Strategy: If push is only once, it reduces traffic and burden to maintain high availability
If content changes frequently users might get stale and out of date content which is undesired
