Api are interfaces that serve as a contract between applications on how they interact
It is set of rules and protocols that allows different software applications to communicate and exchange data with each other

Each component has its api

Best practice
- Complete encapsulation of design and implementation it wuld be bad if knowledge of business logic or implementatio to use it.
We want our api to be complelety decoupled from implementation/design
- Easy to use, understand and impossible to misuse accidentally or intentionally
This can be achived by making only one way to get certain data / perform a task
Descriptive name for action/resource
Exposing only necessary information and action
Consistency across the api
- Idempotent operation (having same result if performed multiple times)
This is wanted because of network decoupling
- Pagination used in case of large payload
This enables clients to handle the data
- Asynchronous operation where client recieves response immediately with an identifier to track operation progress
used in case of big data operation
video compression
- Versioning
This allows us to make changes to design and implementation in case of non backward compatible updates
