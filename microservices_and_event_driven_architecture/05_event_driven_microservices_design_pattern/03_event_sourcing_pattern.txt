Data is usually stored in the db and new state overwrites data and we use backups for previous state adn most operations are crud
This does not work if we need to know every step that leads to the current state e.g bank history
We need visualization, auditing, correction, merchant inventory state to know how we got to current values

We store events that describe changes and as they are immutable adn append new events, we replay events to arrive at current state
For bank account we store transactions and replay it to get current account state, we can notice duplicate transaction, detect fraudulent activities
and audit account.

Benefits
Visualization, Auditing, Corrections, High write performance

- We can store data as events in database to perform query/analytics for orders
